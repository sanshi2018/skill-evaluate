# 实现说明：02 核心状态模型与数据契约（State Schema）

## 交付了什么

`src/skill_evaluate/state/` 完整落地设计文档第 2 节的目录布局与全部模型：

| 文件 | 内容 | 对应设计文档章节 |
|---|---|---|
| `enums.py` | 全局枚举 | 第 3 节 |
| `skill.py` | `SkillReferenceFile` / `SkillScript` / `SkillDefinition` | 第 4 节 |
| `test_case.py` | `TestCase` / `TestSuiteVersion` | 第 5 节 |
| `trace.py` | `TimingCostMetrics` / `ActionStep` / `ArtifactManifestEntry` / `ExecutionTrace` | 第 6 节 |
| `capability.py` | `TIER_WEIGHTS` / `NegativeConstraint` / `CapabilityNode` / `CapabilityTree`（含 `weighted_coverage()`） | 第 7 节 |
| `judge.py` | `JudgeVerdict` / `ConsensusResult` | 第 8 节 |
| `security.py` | `SecurityFinding` | 第 9 节 |
| `assertion.py` | `AssertionSpec` / `AssertionResult` | 第 10 节 |
| `pipeline_state.py` | `PipelineState`（TypedDict + reducer） | 第 11 节 |
| `__init__.py` | 统一导出（`from skill_evaluate.state import ...`） | 第 2 节约定 |

所有字段名、类型、默认值均与设计文档逐字对齐，未做任何"顺手改进"式的重命名
或语义调整——本模块是全项目接口真理来源，改动风险最高，因此严格照抄。

## 与设计文档的差异小结

仅有的调整是**把设计文档中部分标注为裸 `str` 的字段收紧为对应的 `StrEnum`**，
且新增的枚举全部是 `str` 的子类，序列化/反序列化行为与原始 `str` 字段完全
等价，不破坏任何已消费该字段的代码：

| 字段 | 原设计 | 实现 | 为何这样做 |
|---|---|---|---|
| `SecurityFinding.category` | `str`（文档以注释列出 6 个字面量值） | `SecurityFindingCategory` 枚举 | 与设计文档"枚举优先于字符串字面量"的总原则（第 1 节第 4 条）保持一致，文档本身在此处出现了"注释列字面量"与"枚举优先"两条指导的轻微不一致，实现时选择遵循更高优先级的总原则 |
| `AssertionSpec.strategy` | `str`（文档以注释列出 3 个字面量值） | `AssertionStrategy` 枚举 | 同上 |

`state/enums.py` 中另外新增了 `HookWaitStatus`（供 04 模块的 `pending_hooks`/
`human_approvals` 状态字段使用）——这是 04 模块新增表结构时按第 1 节"枚举
优先"原则顺带补的，不影响本模块任何既有字段。

## 如何验证

```bash
pytest tests/skill_evaluate/test_state_contracts.py -q
```

覆盖点：

- `TestCase` happy-path 构造（默认值正确）。
- `CapabilityTree.weighted_coverage()` 三种情形：全覆盖=1.0、P0 未覆盖时即使
  P2 全覆盖也不能虚高（验证设计文档模块八"P0 权重 0.6 占主导"的核心诉求）、
  空节点列表=0.0。

## 消费方现状

按设计文档第 12 节"跨模块交互契约速查表"，目前已经落地的消费关系：

- `executors/`（03）：产出 `ExecutionTrace`，读取 `SkillDefinition`/`TestCase`。
- `persistence/`（04）：为本模块全部模型提供 ORM 落盘（`models.py`）与
  Repository 存取（`repository.py`），字段一一对应，无私自新增字段。
- `observability/`（05）：`report_schema.py::DimensionResult`/`BenchmarkReport`
  引用了 `JudgeVerdictStatus`、`SeverityLevel`。

尚未有消费方的模型（`CapabilityTree`、`JudgeVerdict`/`ConsensusResult`、
`SecurityFinding`、`AssertionSpec`/`AssertionResult` 的生产逻辑）等待
`docs/dev/06~10`、`15~18` 落地，见 `docs/dev/02` 第 13 节"待接入文档"表格，
该表格仍然有效，未被本次实现改写。

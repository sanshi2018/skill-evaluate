# 实现说明：01 项目脚手架与技术栈基线

## 交付了什么

### 目录结构

按设计文档第 2 节的 src-layout 完整落地，包名 `skill_evaluate`：

```
src/skill_evaluate/
├── __init__.py
├── config.py              # 全局配置（本文档 + 02~05 逐步追加）
├── logging.py              # structlog 初始化
├── errors.py                # 项目级异常体系
├── cli.py                    # typer 入口
├── state/                     # 02
├── executors/                  # 03
├── persistence/                 # 04
├── observability/                # 05
├── api/                            # 05（Hook/审批 API 层，设计文档未显式建目录，
│                                     #     由 05 文档第 2 节新增，见该模块 README）
├── agents/{generator,mini,judge,optimizer,validator,analyzer,attacker}/
├── nodes/{trigger_accuracy,context_scoping,instruction_control,
│          script_usability,security,coverage,cross_model,multi_skill}/
├── graph/
└── memory/
```

`agents/`、`nodes/`、`graph/`、`memory/` 下均只有 `__init__.py` 占位（每个文件
开头注明由哪份后续文档实现），未包含业务代码——这是本次任务范围（0~5）之外
的部分，按设计文档"预留目录、不抢跑后续文档"的约定处理。

### 依赖管理

`pyproject.toml` 按设计文档第 3 节落地，额外补充了 05 文档要求追加的
`fastapi`/`uvicorn`/`jinja2` 与 04 文档要求追加的 `alembic`（均以设计文档明确
允许的"追加式扩展"方式写入 `dependencies`，未引入 Poetry/PDM）。

`[tool.ruff]`/`[tool.mypy]`/`[tool.pytest.ini_options]` 均按文档配置；`pytest`
额外增加了两项本文档未提及、但落地时发现必需的配置（均为纯工具行为调整，不
改变任何业务语义）：

- `addopts = "--import-mode=importlib"`：避免 `tests/skill_evaluate/` 与
  `src/skill_evaluate/` 顶层包名相同导致的 pytest 收集期 import 遮蔽问题
  （`tests/skill_evaluate/__init__.py` 因此被删除，测试目录以纯 `importlib`
  模式收集，不再是一个 Python 包）。
- `python_classes = "*Tests"`：`state/test_case.py` 中的 `TestCase` /
  `TestCaseCategory` 是设计文档 02 定义的领域模型/枚举，与 pytest 默认的
  `Test*` 收集规则撞名，收窄规则避免误报 `PytestCollectionWarning`。

### 配置系统

`config.py` 实现了 `DatabaseSettings`/`LLMSettings`/`ExecutorSettings`/
`Settings`/`get_settings()`，字段与设计文档逐一对应。额外新增（均为文档
"新增字段不改语义"约定下的合规追加，由 04/05 文档的需求驱动）：

- `DatabaseSettings.async_dsn`：`persistence/db.py` 的异步 SQLAlchemy engine
  需要 `postgresql+psycopg://` 前缀的 DSN，`dsn`（同步）语义不变，新增属性
  不影响原字段。
- `LangfuseSettings`：对应设计文档 05 第 4 节要求的 Langfuse 开关/密钥配置。
- `ApiSettings`：对应设计文档 05 第 2 节 Hook API 层需要的 host/port/
  `internal_base_url`（`HermesBackend` 拼装回调 URL 时使用，设计文档原文未
  显式定义该配置项，属于必要的补充）。
- `get_settings()` 加了 `@lru_cache`：设计文档原文是无缓存的普通函数，加缓存
  是纯性能优化，不改变返回值语义（`Settings()` 本身无状态，多次构造结果
  一致）。

### 本地开发环境

`docker-compose.dev.yml` 与设计文档第 5 节完全一致。`CREATE EXTENSION IF NOT
EXISTS vector` 未单独作为脚手架阶段的裸 SQL 文件，而是并入了 04 模块的
Alembic 首个迁移 `0001_initial_schema.py`（详见该模块 README）——这是设计
文档第 5 节末尾预留的"迁移框架细节留给 04 决定"的正常延续，不是偏差。

### 代码质量基线 / 异常约定 / CLI 骨架

- `errors.py`：`SkillEvaluateError` 及设计文档列出的 4 个子类全部落地，另按
  04/05 落地过程中的实际需要追加了 `PersistenceError`、`ObservabilityError`
  （均继承自 `SkillEvaluateError`，符合"不脱离体系新建根异常"的约定）。
- `logging.py`：`structlog` 初始化，`env=local` 走彩色控制台、其余走 JSON，
  对应设计文档第 6 节。
- `cli.py`：`run` 命令保留 `NotImplementedError` 桩（等待 24 接入主图）；
  `db_init` 命令**已经是真实实现**（不再是桩）——见 04 模块 README，这是
  04 文档明确要求"本文档正式实现该命令"的产出，只是物理文件仍是脚手架阶段
  建的 `cli.py`。

## 与设计文档的差异小结

| 差异点 | 类型 | 说明 |
|---|---|---|
| `pytest` 两项 ini 配置 | 工具行为修正 | 解决 src-layout 下的包名撞名问题，不影响业务代码 |
| `get_settings()` 加 `@lru_cache` | 性能优化 | 行为等价，无状态单例 |
| `ApiSettings` | 必要补充 | 03/05 的 Hook 回调 URL 拼装需要，原文档未定义 |
| `DatabaseSettings.async_dsn` | 必要补充 | 04 的异步 ORM 需要，同步 `dsn` 字段不变 |

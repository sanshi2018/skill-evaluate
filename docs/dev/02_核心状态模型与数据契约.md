## 1. 设计原则

1. **LangGraph 的 `PipelineState` 是唯一的图级共享状态**，所有节点读写都通过它；节点内部私有的中间变量不进 `PipelineState`。
2. **`PipelineState` 本身尽量薄**：只放"跨节点必须共享"的引用/摘要字段，重量级数据（完整 Trace Tree、完整测试集）落库（Postgres），`PipelineState` 里只存主键/版本号，避免 Checkpoint 序列化体积失控（这对 `PostgresSaver` 的追加日志尤其重要，见文档 04）。
3. **所有跨模块数据结构用 Pydantic v2 定义**，且全部放在 `state/` 包下按子域拆文件，不允许某个 `nodes/` 子目录私自定义会被其他模块消费的模型。
4. **枚举优先于字符串字面量**：状态机的各种"判定结果""严重级别""执行后端类型"一律用 `StrEnum`，避免后续模块用字符串比较时出现拼写不一致的隐性 bug。
5. **向后兼容的扩展方式**：后续文档如需在既有模型上加字段，只能"新增可选字段（带默认值）"，不得修改/删除已确认字段的类型语义——这是本项目对多轮文档确认流程的接口稳定性承诺。

```python
from pydantic import BaseModel, Field


class SkillReferenceFile(BaseModel):
    path: str                       # 相对 skill 根目录的路径，如 "references/errors.md"
    trigger_condition: str | None = None  # 主 SKILL.md 中声明的按需加载触发条件（模块二审查用）
    token_estimate: int | None = None


class SkillScript(BaseModel):
    path: str                       # 如 "scripts/parse_csv.py"
    exposed_tool_name: str | None = None  # 模块十命名空间冲突检测用
    supports_help_flag: bool | None = None  # 模块四黑盒探测填充


class SkillDefinition(BaseModel):
    """对一份被测 Skill 的静态结构化快照，来自解析 SKILL.md 及其目录"""
    skill_id: str                    # 稳定标识，建议用仓库路径的 slug
    version_ref: str                  # git commit sha 或 tag，保证可追溯
    root_path: str
    description: str                    # SKILL.md 顶部 description 字段原文
    body_markdown: str                    # SKILL.md 正文全文
    line_count: int
    token_count: int
    reference_files: list[SkillReferenceFile] = Field(default_factory=list)
    scripts: list[SkillScript] = Field(default_factory=list)
```

## 7. 能力树（`capability.py`，对应模块六/七/八）

```python
from pydantic import BaseModel, Field
from .enums import  StrEnum


class CapabilityTier(StrEnum):
    P0_CORE = "p0_core"           # 权重 0.6
    P1_CONDITIONAL = "p1_conditional"  # 权重 0.3
    P2_DEFENSIVE = "p2_defensive"        # 权重 0.1


TIER_WEIGHTS: dict[CapabilityTier, float] = {
    CapabilityTier.P0_CORE: 0.6,
    CapabilityTier.P1_CONDITIONAL: 0.3,
    CapabilityTier.P2_DEFENSIVE: 0.1,
}


class NegativeConstraint(BaseModel):
    """SKILL.md 中的 Gotchas/避坑指南，模块八反事实追踪对象"""
    constraint_id: str
    description: str
    covered: bool = False
    covering_case_ids: list[str] = Field(default_factory=list)


class CapabilityNode(BaseModel):
    capability_id: str
    skill_id: str
    description: str
    tier: CapabilityTier
    covered: bool = False
    covering_case_ids: list[str] = Field(default_factory=list)


class CapabilityTree(BaseModel):
    skill_id: str
    skill_version_ref: str
    nodes: list[CapabilityNode] = Field(default_factory=list)
    negative_constraints: list[NegativeConstraint] = Field(default_factory=list)
    combinatorial_pairs_covered: list[tuple[str, str]] = Field(default_factory=list)  # 模块七组合矩阵

    def weighted_coverage(self) -> float:
        if not self.nodes:
            return 0.0
        total = sum(TIER_WEIGHTS[n.tier] for n in self.nodes)
        covered = sum(TIER_WEIGHTS[n.tier] for n in self.nodes if n.covered)
        return covered / total if total else 0.0
```

## 11. `PipelineState` 本体（`pipeline_state.py`）

```python
from typing import TypedDict, Annotated
from operator import add
from .enums import NodeExecutionStatus


class PipelineState(TypedDict, total=False):
    # ---- 运行身份 ----
    run_id: str
    skill_id: str
    skill_version_ref: str

    # ---- 引用型字段：只存主键/版本号，不存整块大对象 ----
    active_suite_version_id: str | None
    capability_tree_id: str | None

    # ---- 累加型字段：LangGraph reducer 用 operator.add 做追加合并 ----
    executed_trace_ids: Annotated[list[str], add]
    judge_verdict_ids: Annotated[list[str], add]
    security_finding_ids: Annotated[list[str], add]

    # ---- 控制流字段 ----
    generation_mode: str            # GenerationMode 枚举值，运行入参
    node_status: dict[str, str]     # {node_name: NodeExecutionStatus}
    suspended_reason: str | None
    retry_counts: dict[str, int]    # {node_name: count}，Optimizer 闭环重试计数

    # ---- 报告聚合（05 文档消费） ----
    final_report_ref: str | None
```

**设计取舍说明：**
- 用 `TypedDict` 而非 Pydantic `BaseModel` 作为 `PipelineState`，是 LangGraph 官方推荐的做法（原生支持 reducer 语义如 `Annotated[list, add]`），重量级校验交给写入前的 Pydantic 模型（如 `TestCase`、`ExecutionTrace`）各自负责。
- `PipelineState` 里一律存 ID/引用，真实内容通过 `persistence/`（文档 04）按 ID 读写 Postgres——这直接决定了 `PostgresSaver` 的 Checkpoint 体积可控，也让"从断点恢复"（文档 04/22）不需要反序列化整棵 Trace Tree。

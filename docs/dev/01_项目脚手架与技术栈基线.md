**选型理由（简）：**
- `langgraph-checkpoint-postgres` 官方提供 `PostgresSaver`，与文档 00 的持久化基线直接对应。
- `pgvector` + `sqlalchemy`：模块八/二十三的向量检索共用同一 ORM 层，避免重复连接池管理。
- `langfuse` 放进可选依赖组：可观测性双写是"增强能力"，本地开发/单元测试不强制要求 Langfuse 账号。
- `testcontainers[postgres]`：单元/集成测试用临时容器起 Postgres+pgvector，不依赖开发者本机常驻服务，也不污染 CI Runner。
- 不引入 Poetry/PDM：保持与 CI 容器化环境的最小摩擦（`pip install -e ".[dev]"` 即可）。

## 4. 配置系统

统一用 `pydantic-settings`，来源优先级：**环境变量 > `.env` 文件 > 代码默认值**。所有后续模块的可配置项都在此文件中新增字段，禁止在业务代码里散落 `os.environ.get(...)`。

`src/skill_evaluate/config.py`（骨架，字段会随 02~24 逐步补充，此处只定最小可用集）：

```python
from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class DatabaseSettings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="SKILLEVAL_DB_")

    host: str = "localhost"
    port: int = 5432
    user: str = "skill_evaluate"
    password: SecretStr = SecretStr("")
    database: str = "skill_evaluate"

    @property
    def dsn(self) -> str:
        return (
            f"postgresql://{self.user}:{self.password.get_secret_value()}"
            f"@{self.host}:{self.port}/{self.database}"
        )


class LLMSettings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="SKILLEVAL_LLM_")

    provider: str = "anthropic"
    judge_model: str = "claude-sonnet-5"     # Judge Agent 默认模型（08 会细化多副本策略）
    mini_agent_model: str = "claude-haiku-4-5-20251001"  # Mini Agent 走更便宜的模型
    api_key: SecretStr = SecretStr("")


class ExecutorSettings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="SKILLEVAL_EXECUTOR_")

    backend: str = "mini"          # "mini" | "hermes" | <其他可插拔后端名>，03 文档定义枚举
    hermes_endpoint: str | None = None
    hermes_hook_secret: SecretStr = SecretStr("")
    sandbox_wall_clock_timeout_s: int = 60   # 模块五：单沙箱存活硬上限

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        env_nested_delimiter="__",
        extra="ignore",
    )

    env: str = "local"              # local | ci | prod
    db: DatabaseSettings = DatabaseSettings()
    llm: LLMSettings = LLMSettings()
    executor: ExecutorSettings = ExecutorSettings()


def get_settings() -> Settings:
    return Settings()
```

## 6. 代码质量基线

- **Lint/Format**：`ruff`（含 `ruff format`），CI 中作为独立 job，失败即阻断（Hard Fail，与架构文档"语言坏味道审查"的严格程度保持一致的工程文化）。
- **类型检查**：`mypy --strict`。所有跨模块共享的数据结构（`state/` 下的 Pydantic 模型）必须有完整类型标注——这些模型是后续文档接口对齐的基础，类型错误在这里被压根挡住比运行时报错更划算。
- **测试**：`pytest` + `pytest-asyncio`（LangGraph 节点大多是异步的）+ `testcontainers`（集成测试起真实 Postgres）。约定单元测试对每个 Agent/Node 至少覆盖一条 happy-path 和一条 fallback 分支。
- **日志**：`structlog`，统一 JSON 输出（CI 环境）或彩色控制台输出（本地，由 `env` 配置项切换）。所有 Agent 调用、LangGraph 节点进入/退出必须打点 `run_id`、`skill_id`、`node_name`，为文档 05 的可观测性打点预留字段一致性。

## 7. 异常约定

定义一套项目级异常基类，后续所有模块复用，禁止裸抛 `Exception`：

```python
class SkillEvaluateError(Exception):
    """项目级异常基类"""

class ConfigurationError(SkillEvaluateError):
    """配置缺失或非法"""

class ExecutorBackendError(SkillEvaluateError):
    """执行引擎适配层错误（03 文档细化子类：超时/挂起/协议不匹配等）"""

class JudgeConsensusError(SkillEvaluateError):
    """裁判未达成共识，需要人工仲裁（08 文档细化）"""

class PipelineSuspended(SkillEvaluateError):
    """需要 interrupt_before 挂起等待人工审批（04/09/22 文档细化）"""
```

这些异常类放在 `src/skill_evaluate/errors.py`，后续文档新增子类而不重新定义基类。
